## 雙頁 fixture 互動驗證

已建立不含使用者資料的兩頁 PDF fixture，內含電子郵件、地址、電話、身分證字號、日期及 IP 位址等規則測試內容。開發伺服器已重新啟動，並透過瀏覽器的 `File` 與 `DataTransfer` 事件注入 fixture；下一步將檢查 PDF.js 是否完成兩頁解析、去識別化後是否顯示逐頁視覺比較，以及頁碼控制是否能切換第二頁。

PDF.js 已在瀏覽器本機成功解析 fixture 的兩頁文字；去識別化完成並找到 5 處替換：電子郵件、電話、身分證字號、日期與 IP 位址。結果區已顯示「預覽並下載 PDF」入口，下一步將打開視窗驗證原始／去識別化後畫面、遮罩與第二頁切換。

首次自動化點擊「預覽並下載 PDF」後，畫面未立即呈現對話框；目前已確認按鈕仍存在，正進一步檢查事件觸發與本機 PDF 視覺比較元件的載入狀態。此現象尚未判定為使用者端功能失敗，需以可觀測的 DOM 狀態再確認。

直接觸發同一按鈕的原生 click 事件後，Dialog 已正確開啟，並顯示「第 1 / 2 頁」、「5 處替換」、「上一頁／下一頁」與「正在本機渲染第 1 頁…」。因此功能事件本身正常；先前未開啟為自動化視窗定位行為，並非 React 狀態或 Dialog 接線錯誤。下一步將等待畫布渲染完成並檢查第二頁切換。

第一頁完成渲染後，Dialog 會以左右兩張 Canvas 保留原始 PDF 版面；右側顯示「1 處遮罩」，對應該頁的電子郵件命中。按下「下一頁」後頁碼已更新為「第 2 / 2 頁」，右側顯示「4 處遮罩」，對應電話、身分證字號、日期與 IP 位址；原始／去識別化後的雙欄版面與上一頁／下一頁控制均正常運作。

視覺檢查發現通用 Dialog 的 `sm:max-w-lg` utility 會壓縮 PDF 比對視窗，因此已以元件專用 `max-width` 覆寫並將比對區最大高度提高到 64vh。修正後，在一般桌面視窗可同時清楚檢閱兩張原始比例頁面；每張頁面的紙張版面、圖片與字型皆保持 PDF.js 渲染結果，右側只加上琥珀色遮罩與替換標記。窄版螢幕維持單欄堆疊，避免將頁面縮到難以閱讀。

目前位置遮罩以 PDF 內嵌文字層的座標為準，因此適用於可選取文字的 PDF。掃描型 PDF 仍可保留原始影像與 OCR 後文字結果；若需要讓掃描影像也有逐字精確遮罩，需在後續版本保留 OCR 字詞座標並進行額外的人工覆核。
