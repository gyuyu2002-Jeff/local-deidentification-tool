# 操作流程體驗改善討論稿

**範圍：** 無意識-去識別化工作站目前的文字、Excel／Word／PDF 文件處理旅程。  
**判讀基礎：** 現有首頁、PDF 預覽與下載流程的實作；未使用外部資料或使用者行為分析。

## 目前旅程的優點

目前流程已具備清楚的三段結構：使用者放入文字或檔案，設定去識別化規則，再檢查差異並下載結果。這套結構符合「原文不離開裝置」的信任敘事，且 PDF 已有預覽、手動遮蔽、固定操作列與下載入口；相較於一般上傳式工具，使用者能在匯出前保有較多的控制權。

真正的改善重點不是增加更多按鈕，而是讓每一個階段都清楚回答使用者的下一個問題：**現在完成了什麼？接下來該做什麼？是否已可安全下載？**

## 建議的目標旅程

> 放入資料 → 系統摘要與建議 → 確認規則 → 執行 → 集中覆核 → 安全下載

| 階段 | 現況 | 主要摩擦點 | 建議介面行為 |
|---|---|---|---|
| 1. 放入資料 | 可貼文字、拖放或選擇多種檔案 | 新手不易判斷該貼文字或上傳檔案；OCR 等待時不確定下一步 | 將入口分成「貼上文字」與「處理文件」兩個明確選擇；解析後顯示檔案類型、頁數、OCR 狀態與下一步按鈕。 |
| 2. 選擇規則 | 可收合群組、搜尋、全選與自訂關鍵字 | 規則很多，使用者可能不知道哪些與報價單、合約或客戶資料最相關 | 解析後顯示「建議規則」與「偵測到的欄位」；提供「報價單／客戶名單／自由文字」快速範本。 |
| 3. 執行處理 | 主按鈕可執行並顯示替換數量 | 執行前缺少安全摘要，使用者不易確認規則是否符合目的 | 主按鈕上方加入一行預檢，例如「已啟用 12 項規則，另有 3 個自訂關鍵字」。 |
| 4. 覆核結果 | 可看文字差異；PDF 可預覽、添加手動遮蔽、全螢幕 | 差異、PDF 預覽與下載入口分散，使用者需要自行判斷是否已檢查完畢 | 結果卡頂端改為「覆核清單」：已遮蔽數、人工遮蔽數、待注意規則、下一步「開啟預覽」。 |
| 5. 下載輸出 | PDF 已有預覽工具列下載；其他格式可直接下載 | 使用者可能不確定下載的是最終版本，或不清楚下載後原文是否被保留 | 下載前顯示精簡確認句：「已套用 17 處自動遮蔽、1 處手動遮蔽；輸出僅在此裝置產生。」 |

## 最值得優先實作的三項

### 1. 文件解析後的「建議規則」卡

這是**最高影響、低至中等成本**的改善。使用者上傳報價單後，不必面對全部規則自行猜測，而是先看到系統辨識到的資料型態與建議啟用組合。例如，偵測到「客戶名稱、聯絡人、電話、地址、統一編號」時，可提供一鍵套用但仍允許展開微調。

這項設計不必宣稱自動判斷完全正確；文案應是「建議先啟用以下規則，請在執行前確認」，以保留本工具的專業與可控性。

### 2. 結果頁的「覆核完成度」

目前使用者看到結果後，必須自己決定要看差異、開啟 PDF，還是下載。建議將結果頁改為小型任務清單：先看替換摘要，再依檔案類型引導「檢查差異」或「開啟 PDF 預覽」，最後才突出下載。

這會把下載按鈕從單純的輸出動作，轉成「已完成檢查後的最後一步」，尤其適合包含客戶資料的報價單與合約。

### 3. 手機版底部固定的下一步操作

手機上捲動較長時，主要行動按鈕容易離開視野。建議在有輸入內容、處理結果或 PDF 預覽時，顯示精簡的底部固定操作列，依目前階段只呈現一個主要行動：**設定規則、執行去識別化、檢查 PDF、下載結果**。次要功能維持在原位置，不將畫面變成大量浮動按鈕。

## 可延後處理的改善

| 項目 | 建議原因 |
|---|---|
| 最近使用的規則組合 | 對熟練使用者有效，但應先確認本機保存設定是否符合使用者的隱私期待。 |
| 批次處理多個文件 | 商業價值高，但需要先定義每份文件的覆核與下載策略，避免降低遮蔽品質。 |
| 規則推薦的更進階自動化 | 可在快速範本穩定後再擴充，避免第一次就引入難以解釋的自動決策。 |

## 建議的下一輪範圍

建議下一輪先落地「**解析後建議規則 + 結果覆核清單**」。兩者可以串成明確的安全旅程：使用者先知道該選什麼，再知道是否已檢查到足以下載。待這兩點穩定後，再加入手機底部固定下一步操作列。

## 請確認的決策

1. 你希望快速範本先以哪一類文件為主：**報價單／合約／客戶清單／一般文字**？
2. 下載 PDF 前，是否要設為「必須開啟預覽一次」才能下載，還是維持使用者可直接下載？
3. 手機底部固定按鈕，你偏好只顯示單一主要動作，還是主要動作加上「更多」選單？
